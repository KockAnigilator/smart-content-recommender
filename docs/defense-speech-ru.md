# Защитное слово по презентации

## Слайд 1. Цель и задачи проекта

Добрый день, уважаемая комиссия.  
Тема моей дипломной работы - система персональных рекомендаций контента на основе действий пользователя.

Цель проекта - разработать систему, которая формирует персональные рекомендации по истории взаимодействий.

Для достижения цели я поставил три задачи:
1) реализовать backend-инфраструктуру с безопасностью и ролевой моделью;  
2) реализовать несколько алгоритмов рекомендаций и explainability;  
3) реализовать два клиента - Web и WPF - с пользовательским и административным функционалом.

---

## Слайд 2. Описание проблемы

Проблема проекта связана с тем, что объем контента растет, а поиск вручную становится неэффективным.

Без персонализации пользователи тратят больше времени на поиск, снижается вовлеченность, а ручная модерация не масштабируется.

Поэтому нужен механизм, который автоматически анализирует действия пользователя и предлагает релевантный контент.

---

## Слайд 3. Цель и задачи проекта (повтор)

На этом слайде я фиксирую цель и задачи как основу всей разработки.

Ключевая идея проекта - пройти полный цикл:  
от хранения действий пользователя -> до персонализированной выдачи -> до интерфейсов для пользователя и администратора.

---

## Слайд 4. Актуальность и целевая аудитория

Тема актуальна, потому что рекомендательные системы уже стали стандартом в цифровых сервисах.

Практическое применение:
- образовательные платформы;
- медиа-сервисы;
- e-commerce.

Целевая аудитория:
- обычные пользователи, которым нужна релевантная выдача;
- администраторы, которым нужен контроль данных и контента;
- аналитики, которым важны метрики качества рекомендаций.

---

## Слайд 5. Архитектура приложения

Проект построен по подходу Clean Architecture:
- Domain - бизнес-сущности;
- Application - интерфейсы и сценарии;
- Infrastructure - работа с БД, реализация сервисов, безопасность;
- WebAPI - REST-эндпоинты.

Клиентская часть реализована в двух вариантах:
- Web-клиент на ASP.NET Core MVC + Razor;
- Desktop-клиент на WPF с MVVM.

Для API используется Swagger, что упрощает тестирование и демонстрацию.

---

## Слайд 6. База данных: структура и связи

В основе - PostgreSQL и Entity Framework Core.

Ключевая таблица - `user_actions`: именно она фиксирует поведение пользователя (`View`, `Like`, `Click`).

Через связи пользователей, контента, категорий и тегов формируется профиль интересов и вычисляются персональные рекомендации.

## Слайд 7. Стек технологий

Основной стек:
- C#, .NET 9, ASP.NET Core Web API;
- PostgreSQL + Entity Framework Core;
- JWT, role-based access, rate limiting, lockout;
- xUnit для тестирования;
- Swagger UI для API-документации.

Этот стек выбран, потому что он дает:
- надежный backend;
- удобную разработку и тестирование;
- масштабируемость и хорошую интеграцию компонентов между собой.

---

## Слайд 8. Алгоритмы рекомендаций

В проекте реализованы 3 алгоритма:

1. Popular - ранжирование по весам действий: View=1, Click=2, Like=3.  
2. By Categories - приоритет категориям, где пользователь наиболее активен.  
3. KNN - поиск похожих пользователей и рекомендация их релевантного контента.

Также реализован explainability-механизм:  
каждая рекомендация может быть объяснена по факторам `Popularity`, `CategoryAffinity`, `KnnSimilarity`.

# Шпаргалка: что говорить на вопросах комиссии

## 1) Какие паттерны используются

- **Clean Architecture** - разделение ответственности по слоям.
- **Dependency Injection** - внедрение зависимостей через контейнер ASP.NET Core.
- **Repository/Service style (через EF + сервисы)** - бизнес-логика вынесена в сервисы.
- **MVC** - в Web-клиенте.
- **MVVM** - в WPF-клиенте.
- **DTO pattern** - отдельные модели для обмена между слоями и по API.
- **CQRS-light по смыслу** - разделение запросов чтения и команд записи на уровне контроллеров/сервисов.

## 2) Почему такие технологии

- **C#/.NET 9** - современная платформа, высокая производительность, сильная экосистема.
- **ASP.NET Core Web API** - быстрый и удобный REST backend.
- **Entity Framework Core** - сокращает рутинный SQL-код, удобные миграции.
- **PostgreSQL** - надежная реляционная БД, подходит для аналитических запросов.
- **WPF + MVC** - демонстрация двух клиентских каналов (desktop и web) в одном проекте.
- **Swagger** - ускоряет тестирование API и защиту проекта.
- **xUnit** - стандарт для unit-тестов в .NET.

## 3) Почему выбран такой алгоритмический набор

- **Popular** решает cold-start и дает стабильную базовую выдачу.
- **By Categories** быстро персонализирует рекомендации даже при небольшом количестве действий.
- **KNN** дает более глубокую персонализацию за счет похожих пользователей.
- **Explainability** повышает доверие к рекомендациям и делает систему прозрачной.

## 4) Что с безопасностью

- JWT-аутентификация.
- Ролевой доступ (Admin/User).
- Rate limiting для login/register.
- Базовый in-memory lockout при множественных неудачных входах.
- Проверка сложности паролей.

3. Вход под `admin@local`, управление пользователями/контентом, DB Viewer, экспорт CSV/PDF.  
4. Swagger: показать 1-2 ключевых endpoint.

## 6) Сильные стороны проекта

- Полный сквозной цикл: сбор действий -> рекомендации -> объяснение -> метрики.
- Два клиента (Web + WPF).
- Админ-функции и экспорт отчетности.
- Готовность к масштабированию и дальнейшей декомпозиции на микросервисы.
